## 0. 원칙

1. 매칭 엔진은 **순수 함수**다. 입력(후보·관계·회차·설정) → 출력(테이블·배치 로그·실패자). DB·시각·외부 호출 없음.
2. **결정적(deterministic)**이어야 한다. 같은 입력이면 항상 같은 결과. 동점은 `application_id` 오름차순으로 결정한다. 랜덤 사용 금지.
3. **필수 조건은 절대 완화하지 않는다.** 선호 점수가 아무리 높아도 필수 조건 위반 조합은 만들지 않는다. [PRD 7.3]
4. 결과는 **설명 가능**해야 한다. 모든 배치·재배치·실패에 사유 코드와 문장을 남긴다. [CTO 09]
5. 이미 `CONFIRMED`인 참가자는 다시 다루지 않는다 (재실행 안전). [PRD 7.3]

## 1. 입력과 출력

### 입력
| 항목 | 내용 |
|---|---|
| `slots` | 이번 실행 대상 회차 (`match_run_at`이 도래한 회차 전부) |
| `candidates` | 대상 회차 중 하나 이상을 선택한, 매칭 상태 `WAITING`인 신청 (프로필 포함) |
| `futureSlotIds` | 후보가 선택했지만 이번 실행 대상이 아닌 회차 (매칭 시각 미도래) |
| `blockedPairs` | 차단·신고·`AVOID` 관계 (양방향으로 취급) |
| `encounters` | 이전에 같은 테이블에서 만난 쌍 |
| `openTables` | 이전 실행에서 확정되었고 자리가 남은 테이블 (확정 후 취소 재배치용, 6장) |
| `config` | 가중치, 최소 점수, 탐색 반복 횟수 등 (9장) |

### 출력
| 항목 | 내용 |
|---|---|
| `tables` | 확정할 테이블 목록 (회차, 멤버, 점수, 요약) |
| `placementLogs` | 참가자별 배치·재배치·실패 기록 (사유 코드 포함) |
| `deferred` | 이번엔 배치 못 했지만 이후 회차 매칭이 남은 참가자 → `WAITING` 복귀 |
| `failed` | 모든 선택 회차에서 실패 → `ALTERNATIVE_OFFERED` |
| `summary` | 생성·분리·병합·재배치·확정·실패 건수 |

## 2. 필수 조건 (Hard Constraints) [PRD]

하나라도 위반하면 그 조합은 존재할 수 없다.

| 코드 | 조건 | 검사 시점 |
|---|---|---|
| H1 | 신청 `SUBMITTED` + 결제 `PAID` | 후보 추출 |
| H2 | 계정 `ACTIVE`, 유효한 참가 제한 없음 | 후보 추출 |
| H3 | 테이블 회차가 모든 멤버의 선택 회차에 포함 (날짜·지역 일치) | 배치·재배치 |
| H4 | 테이블 인원 4~6명 | 확정 전 검증 |
| H5 | 최고령자와 최연소자 출생연도 차이 ≤ 8 | 배치·재배치 |
| H6 | 멤버 간 차단·신고·`AVOID` 관계 없음 (어느 한쪽이라도) | 배치·재배치 |
| H7 | 한 참가자는 같은 날짜에 확정 테이블 1개 이하 | 확정 전 검증 |

> 나이는 출생연도만 받으므로 **출생연도 차이**로 계산한다. [결정]

## 3. 선호 점수 (Soft Score)

필수 조건을 통과한 테이블에만 계산한다. 각 항목을 0~1로 계산한 뒤 가중치를 곱해 **총점 0~100**.

### 3-1. 가중치 [결정]

PRD 우선순위(연령대 → 성비 → MBTI → 관심사 → 만나고 싶은 사람)를 가중치 내림차순으로 반영하고, MAT-06(새로운 사람 우선)을 추가했다.

| 순위 | 코드 | 항목 | 가중치 |
|---|---|---|---|
| 1 | S1 | 연령 밀집도 | 20 |
| 2 | S2 | 성비 | 20 |
| 3 | S3 | MBTI 구성 | 18 |
| 4 | S4 | 공통 관심사 | 16 |
| 5 | S5 | 희망 상대 성향 충족 | 14 |
| 6 | S6 | 새로운 사람 비율 | 12 |
| | | **합계** | **100** |

### 3-2. 항목별 계산

**S1 연령 밀집도** — 8살 이내(필수) 안에서도 가까울수록 좋다.
```
spread = max(birth_year) - min(birth_year)        // 0~8
S1 = 1 - spread / 16                              // 0살 차 1.0, 8살 차 0.5
```

**S2 성비** — 같을수록 좋다. 홀수 인원이면 1명 차이가 최선.
```
diff = |남 - 여|,  ideal = n % 2
S2 = 1 - (diff - ideal) / n                      // 3:3 → 1.0, 4:2 → 0.67, 6:0 → 0.0
```

**S3 MBTI 구성** [결정 · 회사 확인 시 교체]
PRD가 "궁합" 기준을 정의하지 않아, 설명하기 쉬운 **축별 균형**으로 정한다. 대화가 한쪽으로 쏠리지 않도록 각 축(E/I, S/N, T/F, J/P)이 섞일수록 높게 준다.
```
축별 balance = 1 - |A수 - B수| / n
S3 = 0.4 × balance(E/I) + 0.2 × balance(S/N) + 0.2 × balance(T/F) + 0.2 × balance(J/P)
MBTI 미입력자는 계산에서 제외. 입력자 2명 미만이면 S3 = 0.5 (중립)
```
> E/I에 비중을 더 준 이유: 첫 만남 대화 분위기에 가장 직접적으로 영향을 준다.

**S4 공통 관심사**
```
S4 = 공통 관심사가 1개 이상인 쌍의 수 / 전체 쌍의 수
```
보조 정보: 3명 이상이 공유한 관심사는 테이블 요약의 "공통 관심사"로 표시하고 대화 주제 생성에 쓴다.

**S5 희망 상대 성향 충족**
```
각 멤버 i: 
  satisfied_i = (다른 멤버 중 self_traits가 i의 preferred_traits와 하나라도 겹치는 사람 수) / (n - 1)
  preferred_traits가 비어 있으면 satisfied_i = 1
S5 = 평균(satisfied_i)
```

**S6 새로운 사람 비율**
```
S6 = 1 - (이전에 만난 적 있는 쌍의 수 / 전체 쌍의 수)
```

**재회 희망 가점 `[CC 2026-10-21]`** — FDB-04 "다시 만나고 싶음"(`WANT_AGAIN`)을 한쪽이라도 고른 쌍은 (1) S6의 "이전에 만난 쌍"에서 빠져 감점을 받지 않고, (2) 같은 테이블이 되면 쌍당 +2점, 최대 +8점을 총점에 더한다(S1~S6 원점수·가중치는 그대로, 가점이 없으면 기존 점수와 같다). 차단·신고·`AVOID`는 재회 희망보다 항상 우선한다(필수 조건, 완화 없음).

### 3-3. 자동 확정 기준 [PRD 7.0]
- 필수 조건 전체 충족 **그리고**
- 총점 ≥ `matching.min-score` (기본 **55**) [결정]

> 기본값 55의 근거: 성비가 4:2(0.67)이고 MBTI가 한쪽으로 쏠려도, 나이·관심사가 무난하면 통과하는 수준. 시드 데이터로 시연하며 조정한다.

## 5. 매칭 절차

### 5-0. 실행 단위
- 스케줄러가 `match_run_at`이 도래한 회차를 모아 **한 번의 `MatchRun`**으로 실행한다. (MAT-01)
- `run_key` = 대상 회차 ID 목록의 해시. 같은 `run_key`가 `COMPLETED`면 실행하지 않는다.
- 후보는 신청의 `application_slot_choices.priority`(선택 순서) 순으로 회차 선호를 가진다.

### 5-1. 후보 추출
1. 대상 회차를 하나라도 선택한 `WAITING` 신청 중 H1·H2 통과자만 후보로 둔다.
2. 탈락자: H1 위반은 후보 제외(결제 미완료 안내), H2 위반은 `ExceptionCase(DATA_MISSING 또는 SAFETY)`.
3. 후보의 매칭 상태를 `MATCHING`으로 바꾼다 (M2).

### 5-2. 최초 배치 (회차 배정)
1. 각 후보를 **선택 순서 1순위 회차**의 후보군에 넣는다 (이번 실행 대상 회차 중).
2. 회차별 후보군을 만든다.

### 5-3. 회차 내 테이블 구성
각 회차 후보군에 대해:

1. **연령 그룹 나누기**: 출생연도 오름차순 정렬 → **출생연도가 가장 빠른 사람(최연장자)부터** 출생연도 +8 이내인 사람을 한 그룹으로 묶고, 남은 사람으로 반복.
2. **그룹 크기별 처리** (n = 그룹 인원):
   - n < 4 → 전원 미배치. 사유는 회차 후보군 전체가 4명 미만이면 `UNDER_MIN_SIZE`, 후보군은 4명 이상인데 연령 그룹 분리로 4명 미만이 됐으면 `AGE_GAP`
   - n = 4~6 → 테이블 1개
   - n = 7 → 테이블 1개(6명) + 1명 미배치. 6명은 점수가 가장 높은 조합으로 고른다 (7가지 경우 전수 비교)
   - n ≥ 8 → 테이블 수 `k = ceil(n / 6)`, 인원을 최대한 균등하게 (예: 13명 → 5·4·4) **(분리, MAT-09)**
3. **초기 배정**: 성별로 나눈 뒤 나이순으로 k개 테이블에 번갈아 배정 (성비 균형 시작점).
4. **차단 관계 해소**: H6 위반 쌍이 있으면 다른 테이블 멤버와 교환해 해소. 교환으로 해소되지 않으면 위반 쌍 중 `application_id`가 큰 쪽을 미배치 (사유 `BLOCKED_PAIR`).
5. **점수 개선 (로컬 서치)**: 같은 그룹 내 서로 다른 테이블의 두 멤버를 교환해 **두 테이블 점수 합이 오르고 필수 조건을 유지하면** 교환한다. 개선이 없거나 `matching.max-swap-iterations`(기본 500)에 도달하면 종료.
6. 결과 테이블은 **임시 테이블**(미확정)로 둔다.

### 5-4. 점수 검증
- 임시 테이블 중 총점이 최소 점수 미만인 테이블은 해체하고 멤버를 미배치로 돌린다 (사유 `LOW_SCORE`).
- 단, 해체 전 5-3의 5번 교환을 같은 회차의 다른 임시 테이블까지 넓혀 한 번 더 시도한다.

### 5-5. 재배치 (MAT-08, PRD 7.4)
미배치자를 `application_id` 순으로 하나씩, 아래 단계 순서대로 시도한다. 각 단계에서 **들어갈 수 있는 임시 테이블 중 점수 상승이 가장 큰 곳**에 넣는다.

| 단계 | 대상 테이블 | 조건 |
|---|---|---|
| 1 | 같은 회차(같은 날짜·같은 지역)의 다른 임시 테이블 | 인원 < 6, 필수 조건 유지, 넣은 후 최소 점수 이상 |
| 2 | 같은 날짜 · 본인이 선택한 다른 지역 회차의 임시 테이블 | 〃 |
| 3 | 본인이 선택한 다른 날짜 · 같은 지역 회차의 임시 테이블 | 〃 (이번 실행 대상 회차만) |
| 4 | 본인이 선택한 다른 날짜 · 다른 지역 회차의 임시 테이블 | 〃 (이번 실행 대상 회차만) |

재배치에 성공하면 `placementLogs`에 `REALLOCATED`, 단계 번호, 이동 사유를 남긴다.

### 5-6. 병합 (MAT-09)
재배치 후에도 남은 미배치자에 대해:
1. 회차별로 미배치자(해당 회차를 선택한 사람)를 모은다.
2. 4명 이상이면 5-3 절차로 새 테이블 구성을 시도한다.
3. 새로 생긴 테이블이 있으면 5-5를 한 번 더 돌린다.
4. 변화가 없을 때까지 반복 (최대 3회).

### 5-7. 최종 검증 및 확정 (MAT-07, MAT-10)
1. 모든 임시 테이블에 H3~H7을 다시 검사한다.
2. 통과 + 최소 점수 이상 → **확정 대상**. 실패 → 해체 후 멤버 미배치.
3. 확정 대상의 멤버: 최초 배치 그대로면 M3, 재배치를 거쳤으면 M4 → M5.

### 5-8. 미배치자 처리
| 경우 | 처리 | 상태 |
|---|---|---|
| 본인이 선택한 회차 중 **이번 실행 대상이 아닌 회차가 남아 있음** | 다음 매칭을 기다림 | `WAITING` 복귀 (states.md M4a) |
| 남은 선택 회차 없음 | 대체 일정 추천 | `ALTERNATIVE_OFFERED` (M6) |

**대체 일정 추천 규칙**
- 모집 중(`OPEN`)이고 매칭 시각이 아직 오지 않은 회차 중, 본인이 선택하지 않은 회차
- 정렬: 본인이 선택했던 지역 → 다른 지역, 그 안에서 날짜 빠른 순
- 최대 3개 제시

## 6. 확정 후 취소 재배치 (PRD 15장)

확정 테이블에서 1명이 취소해 **4명 미만**이 되면:
1. (P1, MVP 제외) 대기자 자동 충원
2. 남은 멤버를 별도 소규모 실행(`run_key` = `cancel-{tableId}`)으로 재배치. 대상은 **같은 회차에서 자리가 남은 확정 테이블**(`openTables`)이며, 필수 조건과 최소 점수를 그대로 적용한다.
3. 들어간 멤버는 해당 테이블 단체방에 초대하고 안내를 보낸다. 기존 테이블은 `DISSOLVED`, 단체방 `CLOSED`.
4. 자리를 못 찾은 멤버는 `ALTERNATIVE_OFFERED`.

취소 후에도 4명 이상이면 테이블을 유지한다 (점수 재계산 후 기록만 갱신).

### 7-2. 사유 코드
| 코드 | 의미 | 참가자에게 보여줄 문구 (예시) |
|---|---|---|
| `PLACED_FIRST_CHOICE` | 1순위 회차에 바로 배치 | 선택하신 일정에 바로 테이블이 구성되었어요 |
| `REALLOCATED_SAME_SLOT` | 재배치 1단계 | 같은 일정의 다른 테이블로 조정되었어요 |
| `REALLOCATED_OTHER_REGION` | 재배치 2단계 | 같은 날 선택하신 다른 지역 테이블로 조정되었어요 |
| `REALLOCATED_OTHER_DATE` | 재배치 3·4단계 | 선택하신 다른 날짜 테이블로 조정되었어요 |
| `UNDER_MIN_SIZE` | 4명 미만 | 해당 일정에 조건이 맞는 신청자가 부족했어요 |
| `AGE_GAP` | 연령 조건 불충족 | 해당 일정에 연령 조건이 맞는 테이블이 없었어요 |
| `BLOCKED_PAIR` | 차단·비선호 관계 | 해당 일정에 함께 배치할 수 있는 테이블이 없었어요 |
| `LOW_SCORE` | 최소 점수 미달 | 조합 기준을 충분히 만족하는 테이블을 만들지 못했어요 |
| `DEFERRED` | 다음 회차 대기 | 선택하신 다음 일정에서 다시 매칭해요 |
| `NOT_PAID` | 결제 미완료로 후보 제외 (H1) | 결제가 완료되지 않아 이번 매칭에서 제외되었어요. 결제 기한 안에 결제해 주세요 |
| `ACCOUNT_RESTRICTED` | 계정 제한으로 후보 제외 (H2) | 현재 계정 상태로는 매칭에 참여할 수 없어요. 고객센터로 문의해 주세요 |
| `DUPLICATE_DATE` | 같은 날짜 중복 확정 방지 (H7) | 같은 날 다른 일정에 이미 배정되어 이 일정은 제외되었어요 |

> 참가자 문구에는 **다른 참가자의 정보와 상세 점수를 넣지 않는다.** 특히 `BLOCKED_PAIR`는 차단 사실이 드러나지 않게 일반 문구를 쓴다. [PRD MAT-12]

### 7-3. 참가자에게 보여주는 매칭 근거 (확정 시)
- 적용된 기준: "연령대·성비·관심사·대화 성향을 반영했어요"
- 함께 매칭된 이유: 공통 관심사 상위 2개, 연령대(예: 20대 후반~30대 초반), 성비
- 재배치가 있었다면 그 사유 문구
- 상세 점수와 다른 참가자의 개인 정보는 비공개

| E6 | 후보 13명 | 5·4·4 세 테이블 |

| E9 | 출생연도가 넓게 퍼진 10명 (두 연령 그룹 4·6) | 그룹별로 테이블 구성, 그룹 간 혼합 없음 |

## 10. 결정 사항

| # | 항목 | 결정 | 비고 |
|---|---|---|---|
| MD1 | 우선순위 반영 방식 | 가중치 내림차순 합산 (사전식 비교 아님) | 운영자가 가중치 조정 가능 |
| MD2 | 연령 | 8살은 필수, 그 안에서 밀집도 가산 | PRD MAT-03·04 통합 해석 |
| MD3 | MBTI 궁합 | 축별 균형 (E/I 가중) | PRD 미정의. 회사 기준 받으면 S3만 교체 |
| MD4 | 성비 | 동수(홀수면 1명 차)를 최선 | PRD 미정의 |
| MD5 | 최소 점수 | 55 | 시연하며 조정 |
| MD6 | 선택지 목록 | 4장 표 | CTO 자료 화면 기준 |
| MD7 | 회차 선호 | 선택 순서를 우선순위로 사용 | `application_slot_choices.priority` |
| MD8 | 미배치 + 남은 선택 회차 있음 | `WAITING` 복귀 | states.md M4a 추가 |
| MD9 | 알고리즘 | 연령 그룹 → 균등 분리 → 교환 기반 로컬 서치 | 결정적, 수백 명 규모에서 충분 |

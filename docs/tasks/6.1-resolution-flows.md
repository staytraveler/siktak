## 영역 조정 (이번 작업 한정)
결제 환불은 6.x의 핵심이라 **이번엔 V2가 `payment` 패키지에 환불 기능을 추가**한다. V1은 3.4(토스 연동) 전까지 `payment`를 건드리지 않는다.
- `PaymentGateway` 포트에 `cancel(paymentKey, amount, idempotencyKey)` 추가, `MockPaymentGateway` 구현. 기존 메서드는 바꾸지 않는다.

## 작업
1. **참가자 API**
   - `GET /api/v1/me/applications/{id}/resolution` — 추천 회차(이유 포함), 선택지 3개, 응답 기한
   - `POST /api/v1/me/applications/{id}/resolution` body `{choice: TRANSFER|KEEP|REFUND, slotId?}`
2. **TRANSFER (M7, D3)**: 기존 신청 `TRANSFERRED` 종료 → 새 신청(선택 회차 1개, `transferred_from_id`, 같은 `payment_id`, 결제 `PAID`) → M1 `WAITING`. **새 결제 생성 금지.** 대상 회차가 모집 중이 아니면 409.
3. **KEEP (M8, D2)**: `NO_MATCH` + 1회권이면 `user_passes(SINGLE_CREDIT, source_application_id)` 발급, 결제 `REFUND_AVAILABLE → PAID`(P7). 멤버십이면 추가 처리 없음.
4. **REFUND (M8, P6→P8→P9)**: `REFUND_REQUESTED` → `REFUND_PROCESSING` → 게이트웨이 `cancel` → `REFUNDED`. 실패 시 재시도(설정 `policy.refund-retry-max`=3)는 **작업 실행기**(`ScheduledJobRegistry`, 1분 뒤)로, 최종 실패면 `REFUND_FAILED` + `exception_cases(REFUND_FAILED)` (P10).
   - **중복 환불 방지**: `payments.refund_key` 유니크 + 이미 `REFUND_PROCESSING`/`REFUNDED`면 no-op. 동시 두 번 호출 테스트.
   - Mock 게이트웨이에 실패 주입 설정(`siktak.payment.mock.fail-cancel=true`)을 둬서 예외 경로를 시연할 수 있게.
5. **미응답 (M8a, D6·D9)**: `RESOLUTION_TIMEOUT` 작업을 `ScheduledJobHandler`로 등록(`respond_by` 시각). 도래 시 KEEP과 동일 처리, `match_resolutions.resolution_status = AUTO_KEPT`. 기동 시 catch-up 대상.
6. **운영자**: `POST /api/v1/admin/exceptions/{id}/retry-refund`(P11), `.../mark-refunded`(P12, 사유 필수).
7. 화면: `/app/applications/:id`에 실패 시 선택 영역(추천 회차 버튼 + 보관 + 환불) **기능만**. 디자인 없음.

## 1. 식당 자동 배정 `com.siktak.venue.domain.assign`
- 입력: 회차 1개의 확정 테이블들(tableId, 인원, 멤버의 희망 가격대 목록), 그 회차 지역의 식당 재고(venueId, 남은 테이블 수 = max_tables − reserved_tables, 테이블당 최대 인원, 가격대, active)
- 규칙 [결정]
  1. 테이블은 tableId 오름차순으로 하나씩 배정
  2. 후보: active, 남은 테이블 ≥ 1, 테이블당 최대 인원 ≥ 테이블 인원
  3. 정렬: 멤버 희망 가격대와 일치하는 인원이 많은 식당 → 남은 테이블 수 많은 식당 → venueId 오름차순
  4. 배정하면 그 식당 남은 수 −1
  5. 후보가 없으면 미배정 목록에 `VENUE_UNAVAILABLE` (PRD INF-02, 15장: 같은 지역 전부 실패 시에만 예외)
- 출력: 배정(tableId → venueId), 미배정 목록, 예약명 제안(`우연한식탁-{회차일 MMdd}-{테이블 순번}`)
- 테스트: demo-scenario 2장 S1(오크테이블 2, 그린키친 0)에서 S1 테이블 3개 → 2개 배정 + 1개 `VENUE_UNAVAILABLE`. 가격대 우선, 인원 초과 식당 제외, 비활성 제외.

## 2. 대화 주제 선택 `com.siktak.content.domain`
- 입력: 테이블 요약(공통 관심사 상위 순, 멤버 대화 스타일 목록), 콘텐츠 풀(contentId, TOPIC/ICEBREAKER, tags=관심사 코드 또는 GENERAL, 대화 스타일 태그 선택)
- 규칙 [결정] (demo-scenario 7장, CON-02)
  1. 공통 관심사 상위 3개에서 각 1개씩 TOPIC 선택
  2. 3개 미만이면 GENERAL TOPIC으로 채워 **최소 3개**
  3. ICEBREAKER 1개 추가
  4. 같은 태그 안 후보가 여럿이면 `(tableId + contentId)` 기반 결정적 선택 (테이블마다 다르게, 같은 입력이면 같게)
  5. 멤버 대화 스타일이 QUIET 과반이면 대화 스타일 태그가 QUIET인 콘텐츠 우선 (없으면 무시)
- 출력: 선택된 contentId 목록 + 선택 이유(어떤 공통 관심사로 골랐는지)
- **시드 콘텐츠도 같이 만든다**: 관심사 10종 × TOPIC 2개 + GENERAL TOPIC 3개 + ICEBREAKER 5개를 Java 상수나 리소스 JSON으로 (`src/main/resources/seed/conversation-contents.json` 권장). 문구는 자연스러운 한국어로 직접 작성.
- 테스트: 공통 관심사 3개 이상/1개/0개, 결정성, QUIET 우선.

## 3. 대체 일정 추천 `com.siktak.matching.domain.alternative`
- 입력: 미배치 참가자(선택했던 회차들과 그 지역), 전체 회차 목록(id, 날짜, 지역, 상태, match_run_at), `now`, 추천 개수(기본 3)
- 규칙: matching.md 5-8 그대로 — 모집 중(`OPEN`)이고 `match_run_at > now`이고 본인이 선택하지 않은 회차 / 본인이 선택했던 지역 우선 → 그 안에서 날짜 빠른 순 → slotId / 최대 3개
- 출력: 추천 회차 목록(+ 추천 이유: "선택하신 지역" / "다른 지역")
- 테스트: demo-scenario 4장 J2 — user14(성수 선택)에게 S4(성수) → S5(강남) 순서. 마감 지난 회차 제외, 이미 선택한 회차 제외, 0개.

## 4. 확정 후 취소 재배치 (matching.md 6장)
- `MatchingEngine`에 별도 진입점 추가: 남은 멤버 + 같은 회차의 자리 남은 확정 테이블(`openTables`) → 배치 또는 실패
- 필수 조건·최소 점수 그대로. 4명 이상 남으면 유지(점수만 재계산).
- 테스트: E21(5명 중 2명 취소 → 3명 재배치 시도/실패), E22(6→5 유지).

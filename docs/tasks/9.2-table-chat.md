# 9.2 단체방 메시지 전송 + 테이블 식당 정보 (V1)

> 블레이버스: 9. 참가자 앱 화면 → 단체방 화면

9.1 PM 확인 답변: **두 개 다 한다.** V2는 배포 사이트 리허설 중이라 이 작업은 V1이 백엔드까지 맡는다.

## ⚠️ push 규칙
V2가 배포 사이트(Render)에서 12단계 리허설 중이다. push하면 Render가 재시작돼 리허설이 깨진다.
**로컬 커밋까지만 하고 push는 PM이 `pm-to-v.md`로 "push OK"라고 할 때까지 대기.** 기다리는 동안 완료 보고를 써두고 사용자에게 "push 대기"라고 알린다.

## 작업
1. **메시지 전송 API** `POST /api/v1/tables/{tableId}/messages` `{ "content": "..." }` (기존 메시지 테이블 사용, 새 마이그레이션 필요하면 V10)
   - 해당 테이블 확정 구성원만 (아니면 403)
   - 내용 1~500자, 빈 값 400
   - 제재(이용 제한) 계정은 403 (7.2 제재 상태 재사용)
   - 보낸 사람 표시는 기존 메시지 조회 API가 주는 형식에 맞추되 **실명·연락처 노출 금지**(별명/이니셜만)
   - 멱등 불필요(채팅), 상태 전이 없음
2. **테이블 조회 API에 식당 정보 필드 추가**: `venueName`, `venueAddress`, `reservationName`, `mapUrl`(없으면 null). 확정 구성원에게만. 9.1의 NOTICE 문자열 파싱은 **제거**하고 이 필드를 쓴다.
3. **프론트**: 단체방 하단 입력창 + 보내기(시안 Table.html), 전송 후 목록 갱신(TanStack Query invalidate, 짧은 폴링 10초면 충분). 홈 TicketCard·단체방 헤더의 식당/예약명도 새 필드로.
4. 테스트: 비DB 단위 테스트(검증 로직) + 컨트롤러 테스트(403/400). DB 테스트 실행 금지.

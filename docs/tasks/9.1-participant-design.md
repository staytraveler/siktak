# 9.1 참가자 앱 디자인 적용 (V1)

> 작성: 2026-10-19 23:10 · PM클로드 · 담당 V1 · **계획 확인 없이 바로**
> 블레이버스: 9. 참가자 앱 화면 → 화면 디자인 적용
> 먼저 읽기: `docs/design/design-guide.md`, `docs/design/mockup/*.html` (브라우저로 열어 확인)

**규칙**: 프론트만 수정. 백엔드·API·마이그레이션 손대지 않는다(V2가 동시에 배포 사이트에서 통합 검증 중). DB 테스트 실행 금지. 기능 동작은 그대로, 보이는 것만 바꾼다.

## 작업 순서
1. **기반**: 글꼴 로드(`index.html`), Tailwind `@theme` 토큰(가이드 2장), `src/design/assets.ts`, `public/illustrations/*.svg` 4개(시안의 SVG를 파일로 옮김), `<Illustration>` 컴포넌트.
2. **공통 컴포넌트** (가이드 4장): Masthead, HeroBlock, TicketCard, Sticker, Chip, Avatar, 버튼 2종, SectionHeader, BottomNav.
3. **시안 3화면 그대로 구현**
   - 홈(확정 상태) ← `Main.html`
   - 단체방/오늘의 테이블 ← `Table.html` (참가자 별명은 실제 데이터가 있으면 사용, 없으면 관심사 기반 표시. 다른 참가자 개인정보 노출 금지 — 기존 API가 주는 것만)
   - 매칭 실패 해결 ← `Resolve.html` (이동·보관·환불 기존 동작 연결 유지)
4. **나머지 화면은 같은 부품으로 톤 맞추기**
   - 로그인, 프로필 입력, 회차 목록·신청(회차 = TicketCard), 결제(Mock), 홈의 다른 상태(신청 전 / 결제 완료·매칭 대기 / 대체 대기), 알림 목록, 기록·피드백, 체크인
   - 상태별 홈 히어로 문구 예: 대기 "테이블을 차리는 중이에요" (mustard 블록)
5. **운영자 화면**: 글꼴·색 토큰만 적용 (레이아웃 유지).
6. 모바일 390px 기준 확인, 가로 스크롤 없음, 버튼 터치 영역 44px 이상.

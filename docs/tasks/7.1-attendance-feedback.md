## 작업
1. **마이그레이션 V6**: `attendances` (ERD 3-7). 이미 있으면 생략.
2. **참석 상태** (states.md 5장): 매칭 확정(M3·M5) 시 `SCHEDULED` 생성(T1, 이벤트 리스너로 — V2 서비스는 이벤트 발행 한 줄만 허용). 체크인 `POST /api/v1/me/applications/{id}/check-in` (T2, 행사 시작 30분 전 ~ 종료, `policy.checkin-open-minutes`). 참석 취소는 이번엔 제외.
3. **행사 종료 작업** `EVENT_END` (`ScheduledJobHandler`, 행사 종료 시각, 기동 시 catch-up): 미체크인 → `no_show_candidate=true`(T5는 운영자 확정, 8.x 화면에서) / `ATTENDED` 쌍으로 `user_encounters` 생성(MAT-06) / 도메인 이벤트 `EventEndedEvent` 발행 (V2가 피드백 요청 알림에 사용).
4. **피드백 확장** (FDB-02·03, 2.3 것 확장): 테이블 분위기·대화·식당 1~5, 재참여 의향 1~5, 추천 0~10, 코멘트. `ATTENDED`만 제출 가능.
5. **사람별 선호** (FDB-04): 같은 테이블 동석자 목록(이름만) + `WANT_AGAIN`/`AVOID` 선택 → `person_preferences`. **상대에게 절대 비노출** — 조회 API는 본인이 쓴 것만. `AVOID`는 V2 엔진이 이미 다음 매칭에 반영한다(입력만 정확히).
6. **데모 버튼** (`/admin/demo`, demo-scenario 1장):
   - 체크인 일괄: 1회차(S1·S2) 확정자 중 `user13` 제외 전원 체크인
   - 피드백 일괄: 체크인한 사람 중 피드백 없는 사람에게 기본 피드백(4점대) 입력
   - 2회차 신청 투입: 1회차 S1 참석자 전원 + `user25`·`user26`이 S4 신청 + Mock 결제 완료
7. 화면: 신청 상세에 체크인 버튼 / 피드백 폼(만족도·의향·동석자별 선호) — 기능만.

## 목표

GitHub `main`에 푸시하면 **프론트는 Vercel, 백엔드는 Render에 자동 배포**되고,
배포된 프론트 화면에서 백엔드 `/api/v1/health` 응답과 **Neon DB 연결**이 확인된다.

## A. 사용자가 직접 할 일 (계정·대시보드 작업)

Claude Code는 이 단계를 대신하지 않는다. 필요한 시점에 사용자에게 값을 요청한다.

### A1. Neon
1. 프로젝트 생성: 이름 `siktak`, 리전 **AWS Asia Pacific (Singapore)**, Postgres 최신 버전
2. 기본 브랜치 `main` = 운영용. 브랜치 `dev`를 추가 생성 = 로컬 개발용
3. 각 브랜치의 접속 정보(host, database, user, password) 확보
4. **로컬 `.env`**에 dev 브랜치 값 입력 (커밋 금지)

### A2. Render
1. New → **Web Service** → GitHub `siktak` 레포 연결
2. 설정
   - Root Directory: `backend`
   - Runtime: **Docker**
   - Region: **Singapore**
   - Instance Type: **Starter 이상 (Free 금지)**
   - Branch: `main`, Auto-Deploy: On
   - Health Check Path: `/api/v1/health`
3. Environment에 B3의 환경변수 입력 (Neon **main** 브랜치 값)
4. 배포 후 서비스 URL 전달 (예: `https://siktak-api.onrender.com`)

### A3. Vercel
1. New Project → GitHub `siktak` 레포 import
2. 설정
   - Root Directory: `frontend`
   - Framework: Vite (자동 인식)
3. Environment Variables: `VITE_API_BASE_URL` = Render 서비스 URL
4. 배포 후 프론트 URL 전달 (예: `https://siktak.vercel.app`)
5. Render의 `CORS_ALLOWED_ORIGINS`에 이 URL을 넣고 재배포

## B. Claude Code가 할 일

### B1. Dockerfile (`backend/Dockerfile`)
- 멀티 스테이지: 빌드 `eclipse-temurin:21-jdk` → 실행 `eclipse-temurin:21-jre`
- 빌드 단계에서 테스트는 제외 (CI에서 수행)
- 실행 옵션: `-XX:MaxRAMPercentage=75 -XX:+UseSerialGC` (Render Starter 메모리 고려)
- `PORT` 환경변수로 서버 포트 지정 (`server.port=${PORT:8080}`)
- `SPRING_PROFILES_ACTIVE=prod`
- `.dockerignore` 추가 (build/, .gradle/)
- `gradlew` 실행 권한과 LF 줄바꿈 확인 (`.gitattributes` 이미 LF 고정)

### B2. 백엔드 설정
- `application-prod.yml`: DB·JWT·CORS를 전부 환경변수로
- CORS: `CORS_ALLOWED_ORIGINS`(쉼표 구분) 값만 허용, `/api/**`
- Flyway: 기동 시 자동 마이그레이션 (`V1__init.sql`의 shedlock 테이블 생성 확인)
- 헬스체크 응답에 **DB 연결 여부** 추가: `{status, time, db: "UP"|"DOWN"}` (간단한 `SELECT 1`)

### B3. 환경변수 정리
`.env.example`과 `docs/integrations.md`에 아래 키와 설명을 맞춘다.

| 키 | 위치 | 설명 |
|---|---|---|
| `DB_URL` | Render, 로컬 | `jdbc:postgresql://<host>/<db>?sslmode=require` |
| `DB_USERNAME` | Render, 로컬 | |
| `DB_PASSWORD` | Render, 로컬 | |
| `JWT_SECRET` | Render, 로컬 | 32바이트 이상 랜덤 문자열 |
| `CORS_ALLOWED_ORIGINS` | Render | Vercel 프론트 URL |
| `SPRING_PROFILES_ACTIVE` | Render | `prod` |
| `VITE_API_BASE_URL` | Vercel, 로컬 | Render 백엔드 URL |

### B4. 프론트 설정
- `frontend/vercel.json`: SPA 라우팅 rewrite (모든 경로 → `index.html`)
- `/app` 첫 화면에 **배포 확인용 상태 표시**: 백엔드 헬스체크 호출 결과(서버·DB 상태, 서버 시각). 이후 실제 홈 화면으로 교체 예정

### B5. GitHub Actions (`.github/workflows/ci.yml`)
- 트리거: `main` 푸시, PR
- 잡 2개 (병렬)
  - backend: JDK 21 + **Postgres 서비스 컨테이너**(postgres:17) → `./gradlew test`
    - 테스트용 프로필 `test`를 만들고 DB 접속은 `TEST_DB_URL`·`TEST_DB_USERNAME`·`TEST_DB_PASSWORD` 환경변수로 받는다
    - CI는 서비스 컨테이너 값을, 로컬은 Neon `dev` 브랜치 값을 쓴다 (로컬에 Docker 없음)
    - DB가 필요한 테스트는 `@Tag("db")`로 구분해 DB 정보가 없으면 건너뛰게 한다
    - 이번에는 Flyway 마이그레이션이 적용되고 컨텍스트가 뜨는지 확인하는 DB 테스트 1건만 추가
  - frontend: Node LTS → `npm ci` → `npm run lint` → `npm run build`
- 배포는 Render·Vercel의 Git 연동이 담당 (Actions에서 배포하지 않음)

### B6. 문서
- `docs/decisions.md`에 추가: `- 2026-10-17 [기획] DB 통합 테스트: CI는 GitHub Actions Postgres 서비스 컨테이너, 로컬은 Neon dev 브랜치, @Tag("db")로 구분 — 로컬 Docker 없음, Testcontainers 대신 CI 기본 기능 사용`
- `README.md`: 배포 구조 그림(텍스트), 배포 URL 자리, 환경변수 표 링크
- `docs/integrations.md`: Neon·Render·Vercel 항목 추가 (설정값, 대시보드에서 바꾸는 법)

## 작업
1. **마이그레이션 V8**: `safety_reports`, `user_sanctions` (ERD 3-7).
2. **차단** `POST /api/v1/me/blocks {userId}` (같은 테이블에서 만난 사람만) → `user_blocks(USER_BLOCK)`. 상대에게 비노출.
3. **신고** `POST /api/v1/me/reports {userId, reasonType, description}` (같은 테이블 동석자만)
   - 접수 즉시 `user_blocks(REPORT)` 생성 → 다음 매칭에서 분리 (PRD 15장)
   - `exception_cases(SAFETY_REPORT)` 생성 → 운영자 예외 처리함
   - 신고 내용은 피신고자에게 절대 비노출 (SAF-01)
4. **운영자 조치** (SAF-02): `GET /api/v1/admin/reports`, `POST /api/v1/admin/reports/{id}/resolve {action: DISMISS|WARNING|RESTRICTION|PERMANENT_BAN, days?, note}` → `user_sanctions` 기록, RESTRICTION·BAN이면 `users.account_status` 변경(RESTRICTED·BANNED), 예외 RESOLVED. 매칭 엔진은 이미 비ACTIVE 계정을 제외(H2).
   - RESTRICTION 기간 만료 해제는 이번엔 생략 (완료 보고에 적기).
5. **참가 이력** (RET-01) `GET /api/v1/me/history`: 과거 회차 날짜·지역·식당·참석 상태·피드백 제출 여부. 화면 `/app/history`.
6. **다음 일정 추천** (RET-02) `GET /api/v1/me/recommendations`: 모집 중 회차를 이전 참가 지역 우선 → 같은 요일·시간대 → 날짜 순, 최대 3개. 화면은 이력 화면 하단.
7. 화면: 피드백 화면 동석자 옆에 "차단·신고" — 기능만.

## 0. 먼저 (5.2 마무리)
- 배포 환경에서 **네가 직접 curl로** 시드 초기화 → J1 → J3 → J4 → S2 테이블 단체방 메시지(공지·큐레이션·정책·리마인드·콘텐츠) 확인. 결과를 완료 보고에 적어.

## 작업 (`/admin` 하위, 좌측 메뉴)
1. **대시보드 `/admin`** (PRD 11장 "바로 보여야 하는 정보" 전부)
   - 회차별: 신청·결제 완료·확정·대체 대기·환불 수
   - 자동화 지표: 자동 확정률, 자동 재배치 성공률, 자동 환불 완료율, 운영자 개입률(예외 건 / 전체 신청) — PRD 3장 정의대로
   - **처리할 예외** 카드: 유형별 OPEN 건수(조건 충돌·식당 없음·발송 실패·환불 실패·노쇼 후보·미처리 신고) → 클릭 시 예외 처리함 필터
   - API `GET /api/v1/admin/dashboard` 하나로.
2. **예외 처리함 `/admin/exceptions`**: 목록(유형·대상·사유·발생 시각·상태 필터) + 상세 패널에서 유형별 조치 버튼 연결
   - VENUE_UNAVAILABLE → 수용량 늘리기 + 재배정(기존 API) / REFUND_FAILED → 재처리·수동 완료(기존) / NO_SHOW_CANDIDATE → 노쇼 확정(T5)·해제 / SAFETY_REPORT → 신고 상세로 이동(V1 7.2 API) / NOTIFICATION_FAILED → 재발송
   - 처리 시 사유 입력 필수, 처리자·시각 기록
3. **매칭 모니터 `/admin/matching`**: 실행 목록(시각·트리거 SCHEDULER/운영자·대상 회차·요약 건수) → 상세: 테이블 목록 + **배치 로그**(참가자별 결정·재배치 단계·사유 코드·원인) — demo 4단계 "user15 재배치, user14 대기"가 한눈에 보이게
4. **테이블 상세 `/admin/tables/:id`**: 구성원(나이·성별·MBTI·관심사), 점수(S1~S6), PRD 7.2 요약, 식당·예약명, 단체방 메시지 목록, **알림 발송 상태**(대상별 SENT/FAILED)
5. NO_SHOW 확정 API가 없으면 `POST /api/v1/admin/attendances/{id}/confirm-no-show`(T5) 추가 (V1 영역이지만 이 한 개 허용).

## 5.2 PM 답변
- 같은 트랜잭션 동기 이벤트: **승인** (알림은 DB 저장만 하고 실제 발송은 작업 실행기라 롤백 일관성 OK).
- 집합 시간 = 시작 시각, 지도 링크 대체: **승인**.
- `NEXT_SLOT_RECOMMEND`: V1이 7.2에서 다음 일정 추천을 만든다. 발송 계기는 EVENT_END 후 피드백 제출 시점으로, 8.1 끝나고 여유 있으면 연결.

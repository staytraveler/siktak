## 작업
1. **마이그레이션 V7**: `notifications`, `notification_templates` (ERD 3-6). 템플릿 12종 시드(demo-scenario 7장 목록, 문구는 PRD 14장 내용 기반으로 직접 작성).
2. **알림 구조** (`notification`): `NotificationService.enqueue(userId, templateCode, vars, scheduledAt, dedupKey)` → 저장 → 즉시 또는 예약 발송.
   - `NotificationSender` 포트 + `InAppNotificationSender`(DB에 SENT 처리, 참가자 알림함에 노출). CLAUDE.md 8장.
   - 예약 발송은 **`ScheduledJobRegistry` 작업**(`NOTIFICATION_SEND`)으로. DB 폴링 금지.
   - 실패 재시도 3회(`policy.notification-retry-max`) → 최종 실패 시 `exception_cases(NOTIFICATION_FAILED)` (INF-08). Mock 실패 주입 설정 `siktak.notification.mock.fail=true`.
   - `dedup_key` 유니크로 중복 발송 방지.
   - 참가자 API `GET /api/v1/me/notifications`, `POST .../{id}/read`.
3. **상태 변화에 알림 연결** (PRD 14장): 신청 완료, 결제 대기·완료, 재배치 중, 매칭 확정, 매칭 실패(대체 일정 안내), 일정 이동 완료, 환불 요청·완료. 기존 서비스에 이벤트 발행(Spring `ApplicationEventPublisher` + `@TransactionalEventListener(AFTER_COMMIT)`)으로 붙여서 V1 서비스 수정은 **이벤트 발행 한 줄씩**만.
4. **단체방 시스템 공지** (INF-03·05·06): 확정 + 식당 배정 직후 단체방에 `NOTICE`(시간·장소·지도 링크·예약명·집합 시간·식사 가격), `CURATION`(테이블 요약: 연령대·성비·공통 관심사 — 개인정보·점수 없이), 취소 정책. `message_key`로 멱등. 식당 미배정이면 장소는 "확정 후 안내"로 두고, 운영자 재배정 시 공지를 추가로 게시.
5. **리마인드** (INF-07): 확정 시 `REMINDER_D1` 작업을 행사 1일 전 시각으로 등록 → 앱 알림 + 단체방 `REMINDER` 메시지(시간·장소·예약명·취소·노쇼 정책).
6. **대화 콘텐츠 게시** (CON-01~03): 확정 시 `CONTENT_POST` 작업을 행사 시작 시각으로 등록 → 4.2 `TopicSelector`로 주제 3개 이상 + 아이스브레이커 1개를 단체방에 `CONTENT`로 게시. 참가자 API `GET /api/v1/me/applications/{id}/contents`.
7. 데모: J3(행사 1일 전)·J4(행사 시작) 점프 시 위 작업이 실행되어야 한다 (V1 데모 도구는 시계만 옮기므로 작업 등록만 제대로 하면 된다).
8. 화면: 참가자 알림 목록 `/app/notifications`, 단체방 메시지 타입별 표시 — **기능만, 디자인 없음**.

## 범위

### 만드는 것
- 패키지: `com.siktak.matching.domain.engine` (필요 시 하위 `score`, `constraint`)
- **입력 모델** (record): `MatchingInput`(slots, candidates, blockedPairs, encounters, config), `SlotInfo`(id, date, regionId), `Candidate`(applicationId, userId, birthYear, gender, mbti nullable, interests, selfTraits, preferredTraits, slotChoices[priority 순], accountActive, paid), `MatchingConfig`(가중치 S1~S6, minScore=55, maxSwapIterations=500, maxMergeRounds=3, alternativeCount=3)
  - `futureSlotIds`: 후보가 고른 회차 중 이번 실행 대상이 아닌 것 → `Candidate.slotChoices` 중 `slots`에 없는 것으로 판단해도 된다.
- **출력 모델**: `MatchingResult`(tables, placementLogs, deferred, failed, excluded, summary)
  - `ProposedTable`: slotId, members(applicationId 목록), totalScore, scoreDetail(S1~S6 원점수·가중 점수), summary(PRD 7.2 항목: 인원, 연령 min/max/차, 성비, MBTI 구성, 공통 관심사, 희망 성향 충족 여부, 이전 만남 쌍, 충돌 없음)
  - `PlacementLog`: applicationId, decision(PLACED/REALLOCATED/CONFIRMED/FAILED/DEFERRED/EXCLUDED), fromSlot/toSlot, reallocStep, reasonCode, reasonText
- **필수 조건 H1~H7** (`matching.md` 2장), **점수 S1~S6** (3장), **절차 5-1~5-8** (5장), **사유 코드·문구** (7-2)
- 4장 선택지는 enum으로 (`Gender`, `Trait`, `Interest`, `ConversationStyle`). 위치는 `profile` 패키지가 맞으면 거기, 아니면 `matching.domain`에 두고 완료 보고에 적어라.

### 만들지 않는 것 (다른 지시서)
- DB 엔티티·리포지토리·마이그레이션, `MatchRun` 저장, 상태 전이, 스케줄러, API, 화면
- 확정 후 취소 재배치(6장, E21·E22) → 6.x에서
- 대체 일정 **추천 목록 생성**은 엔진 밖(DB의 모집 중 회차 조회 필요). 엔진은 `failed`에 담기만 한다.

## 구현 원칙
- 결정적: 정렬·동점은 `applicationId` 오름차순. `Random`, `HashMap` 순회 순서 의존 금지(`LinkedHashMap`/정렬 사용).
- 필수 조건은 어떤 단계에서도 완화하지 않는다. 교환·재배치·병합 후 항상 재검증.
- 점수 계산은 테이블 단위 순수 함수로 분리해 단독 테스트 가능하게.
- 명세가 모호해 해석이 필요하면 코드 주석 `// [해석]`으로 남기고 완료 보고 "PM 확인 필요"에 적는다. 명세와 다르게 구현해야 하면 멈추고 `v2-to-pm.md`로 묻는다.

## 테스트 (JUnit 5, Spring 없이)
- `matching.md` 8장 중 **E1~E19, E23, E24** 전부. 각 테스트 이름에 케이스 번호를 넣는다 (예: `E3_후보7명_6인확정_1명실패`).
- 점수 단위 테스트: S1(0살/8살 차), S2(3:3, 4:2, 6:0, 5명 3:2), S3(전원 미입력, E/I 균형), S4, S5(빈 희망 성향), S6.
- **시드 시나리오 테스트**: `docs/demo-scenario.md` 3장의 J1 입력(S1·S2, user01~user16)으로 엔진을 돌려 4장 "J1 후" 기대 결과를 검증한다. (식당 배정 제외)
  - S2 6인 확정, user15 `AGE_GAP` → S1 재배치(2단계), user14 `DEFERRED`, user16 `EXCLUDED`(미결제), S1 3개 테이블, user05/user06 다른 테이블.
  - 기대와 다르게 나오면 엔진이 아니라 **명세나 시드가 틀렸을 수 있으니** 임의로 맞추지 말고 `v2-to-pm.md`로 보고.
- `./gradlew test` 전체 통과.

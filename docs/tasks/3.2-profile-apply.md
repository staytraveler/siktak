## 작업
1. **회원가입** `POST /api/v1/auth/signup` (아이디·비밀번호·이름·연락처) → 가입 즉시 로그인 토큰. 프론트 `/signup`. (PRD 17장 화면 목록 "로그인·회원가입")
2. **프로필 엔티티** `profile` 패키지에 `Profile`(ERD 3-1 그대로, 선택지는 V2가 만든 `profile.domain` enum 재사용). V2 엔진은 `profiles`를 SQL로 읽으니 **컬럼명·JSON 형식을 바꾸지 마**.
   - `GET/PUT /api/v1/me/profile`. 검증: 출생연도(만 19~45세 [결정]), 성별, 관심사 1~5개, 본인 성향 1~3개, 희망 성향 0~3개, MBTI 16종 또는 미입력, 가격대 코드 3종, 개인정보·운영정책 동의 둘 다 필수(ACC-05).
   - 화면 `/app/profile`: 한 화면에 섹션 3개(기본 정보 / 매칭 선호 / 식사 조건·동의). 칩 선택식. **최초 신청 5분 이내**(PRD 16장)를 의식해 입력 수를 늘리지 말 것.
3. **신청 정식화** (2.3 것을 확장)
   - 회차 목록 `GET /api/v1/slots`: 모집 중만, 날짜·지역·시간·신청 마감·매칭 예정 시각·남은 자리 (APP-01).
   - 신청: 프로필 미완성이면 400(`PROFILE_INCOMPLETE`)과 함께 프로필 화면으로 안내. 회차 1~5개, 선택 순서 = priority. 같은 회차 중복 신청 409. 마감 지난 회차 409. (APP-02·03)
   - 이용권 선택 화면 자리만(1회권만 동작). 멤버십·크레딧은 3.4.
   - 신청 완료·결제 화면에 **환불·노쇼 정책 문구 노출**(PAY-02): "진행 2일 전부터 환불 불가, 당일 취소 및 단체방 퇴장 불가".
4. 시드 영향: demo-v1 사용자 프로필은 이미 채워져 있으니 그대로 동작해야 한다. demo01은 프로필 완료·신청 전 상태 유지.
